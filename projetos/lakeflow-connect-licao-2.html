Data Ingestion from Cloud Storage

Data Ingestion with Lakeflow Connect · Lição

Em desenvolvimento

Esta lição mostra como arquivos brutos em armazenamento de objetos na nuvem viram tabelas Delta, o que habilita a gestão e as análises avançadas no Lakehouse. Ela apresenta três métodos de ingestão, o CTAS, o COPY INTO e o Auto Loader, e compara quando usar cada um.

Estas anotações partem de um resumo da lição, não do material original. Os trechos de código são exemplos escritos por mim para ilustrar os métodos, com caminhos e nomes genéricos, e não foram executados.

Objetivos

  1. Demonstrar a ingestão de dados do armazenamento em nuvem para tabelas Delta com CREATE TABLE AS, COPY INTO e Auto Loader, inclusive capturando metadados do arquivo de entrada em tabelas Bronze.
  2. Explicar como as colunas rescued são usadas na ingestão para tratar registros malformados.

O padrão de ingestão

A ingestão é peça central do Lakehouse moderno, porque permite aproveitar os grandes volumes de dados guardados na nuvem. O fluxo é:

arquivos (CSV, JSON, Parquet etc.) → método de ingestão (CTAS, COPY INTO ou Auto Loader) → tabela Delta.

Método 1: CREATE TABLE AS (CTAS), em batch

Cria, por padrão, uma tabela Delta a partir de arquivos no armazenamento. O padrão de uso é CREATE TABLE nova_tabela AS SELECT * FROM read_files(...), e a read_files() lê os arquivos de um local e devolve os dados em forma tabular.

  • Formatos suportados: JSON, CSV, XML, TEXT, BINARYFILE, PARQUET, AVRO e ORC.
  • Detecta o formato e infere um schema unificado entre os arquivos, e aceita opções específicas de cada formato.
  • Também pode ser usada em tabelas streaming, para ingerir arquivos de forma incremental via Auto Loader.
CREATE TABLE nova_tabela AS
SELECT * FROM read_files(
    'caminho_do_volume/origem',
    format => 'csv',
    header => true
);

Método 2: COPY INTO

Faz uma carga em massa de arquivos do armazenamento para uma tabela Delta. No exemplo da lição, a tabela de destino está vazia, e o FROM aponta para os CSVs. É ideal quando o local recebe arquivos continuamente: é uma operação repetível e idempotente, pensada para a ingestão batch incremental.

COPY INTO minha_tabela
FROM 'caminho_do_volume/origem'
FILEFORMAT = CSV
FORMAT_OPTIONS ('header' = 'true')
COPY_OPTIONS ('mergeSchema' = 'true');

Método 3: Auto Loader

É a ingestão incremental, em batch ou streaming: processa os novos arquivos conforme eles chegam, sem configuração complexa, detectando e carregando automaticamente em tabelas Delta. Funciona em Python e em SQL (via Declarative Pipelines), escala para bilhões de arquivos e se apoia no Spark Structured Streaming.

Em Python

  • O .readStream com o formato cloudFiles habilita o Auto Loader.
  • Define-se o formato do arquivo (por exemplo, JSON) e o cloudFiles.schemaLocation, que acompanha a inferência e a evolução do schema.
  • O .load() aponta para o caminho, por exemplo em /Volumes, do Unity Catalog.
  • Na escrita, o .writeStream usa um local de checkpoint (estado e progresso) e um trigger (por exemplo, a cada 5 segundos).
  • O .toTable() grava na tabela Delta, no formato catálogo.schema.tabela.
(spark.readStream
    .format("cloudFiles")
    .option("cloudFiles.format", "json")
    .option("cloudFiles.schemaLocation", "caminho_do_schema")
    .load("/Volumes/catalogo/schema/volume/origem")
    .writeStream
    .option("checkpointLocation", "caminho_do_checkpoint")
    .trigger(processingTime="5 seconds")
    .toTable("catalogo.schema.minha_tabela"))

Em Databricks SQL

A recomendação é usar tabelas streaming, em vez do COPY INTO. Uma streaming table é registrada no Unity Catalog, com suporte extra a processamento incremental. Ao criá-la, um pipeline é gerado automaticamente, e ela serve para cargas incrementais do Kafka e do armazenamento de objetos.

A recomendação geral para ingerir do armazenamento em nuvem é o Auto Loader com o Spark Declarative Pipelines, que carregam de forma incremental e idempotente conjuntos de dados que crescem continuamente. Essas tabelas usam pipelines serverless, então o workspace precisa suportar serverless, ou você pode montar os seus próprios pipelines. Para usar o Auto Loader em SQL, usa-se a read_files com a palavra-chave STREAM na cláusula FROM.

CREATE OR REFRESH STREAMING TABLE minha_streaming_table AS
SELECT * FROM STREAM read_files(
    'caminho_do_volume/origem',
    format => 'json'
);

O que guardar: o CTAS com read_files() é a ingestão batch para conjuntos menores e tarefas ad hoc. O COPY INTO é batch incremental, idempotente e repetível, pula os arquivos já carregados e dá controle fino com as opções de formato e de cópia. O Auto Loader é o método mais escalável: baseado em Structured Streaming, funciona em Python e em SQL (Declarative Pipelines), processa bilhões de arquivos e trata a evolução de schema automaticamente.
