Ingesting Semi-Structured Data: JSON

Data Ingestion with Lakeflow Connect · Lição

Em desenvolvimento

Esta lição mostra como a ingestão de dados semiestruturados, como o JSON, permite interpretar e transformar entradas complexas e aninhadas em tabelas Delta estruturadas, prontas para análises avançadas no Lakehouse. Ela compara três abordagens para colunas JSON, STRING, STRUCT e VARIANT, e ensina a derivar e aplicar um schema com schema_of_json e from_json.

Estas anotações partem de um resumo da lição, não do material original. Os trechos de código são exemplos meus, montados a partir do exemplo do "John Doe" do resumo, e não foram executados.

Objetivos

  1. Descrever a estrutura de dados JSON: objetos, chaves, valores, objetos aninhados e arrays.
  2. Explicar três abordagens para colunas JSON: os tipos STRING, STRUCT e VARIANT.
  3. Mapear os tipos JSON para os tipos SQL do Databricks e definir schemas STRUCT para JSON aninhado.
  4. Usar schema_of_json e from_json para derivar e aplicar schemas ao converter strings JSON em colunas STRUCT.
  5. Descrever o tipo VARIANT e os benefícios dele para dados semiestruturados.

Visão geral do JSON

Entender o formato importa porque ele afeta como os dados são interpretados e transformados na ingestão. São três termos:

Objetos

Entre chaves

Os dados JSON são feitos de objetos, normalmente entre chaves {}.

Chaves

Pares chave-valor

A chave é sempre uma string entre aspas e tem um valor associado.

Valores

Vários tipos

String, número, booleano, array, objeto ou null. Os objetos podem ser planos ou aninhados, e entender isso ajuda no parsing e na transformação.

Colunas em formato JSON

Depois da ingestão, é comum que uma ou mais colunas da tabela tenham strings JSON como valores. Isso acontece quando o JSON não foi totalmente interpretado na ingestão, ou quando ele está embutido em outro campo, como uma mensagem de log. O exemplo da lição usa uma json_column com registros como este:

{
  "name": "John Doe",
  "age": 35,
  "address": { "city": "Anytown", "state": "CA" },
  "children": [ { "name": "...", "age": 0 } ]
}

Dá para extrair e manipular essas strings com SQL ou com operações de DataFrame, achatando ou acessando os campos aninhados como colunas normais.

Três abordagens para a coluna JSON

Abordagem 1: STRING

  • O JSON fica guardado como uma simples STRING, com qualquer conteúdo e sem restrições (texto bruto).
  • É menos performática do que as abordagens tipadas.
  • Os subcampos são acessados com a sintaxe de dois-pontos.
SELECT
    json_column:name         AS nome,   -- John Doe
    json_column:address:city AS cidade  -- Anytown
FROM minha_tabela;

Abordagem 2: STRUCT

O JSON é interpretado em um tipo STRUCT com schema definido, que impõe uma estrutura e tipos consistentes. É mais eficiente para consultas do que a string JSON. O mapeamento entre os tipos:

Tipo JSONTipo SQL do Databricks
StringSTRING
NumberINT, FLOAT ou DOUBLE
BooleanBOOLEAN
ObjectSTRUCT<>
ArrayARRAY<>

Abordagem 3: VARIANT

  • É o tipo mais novo para trabalhar com JSON no Databricks, em public preview desde o segundo trimestre de 2025. A lição pede para acompanhar o lançamento GA.
  • Armazena qualquer tipo de dado, inclusive JSON, e é ideal para dados semiestruturados.
  • É altamente flexível, sem schema prévio, e se adapta a diferentes formas de dados.
  • Tem desempenho melhor do que o STRING e o STRUCT.
STRINGSTRUCTVARIANT
EstruturaTexto bruto, sem restriçõesSchema definido, com tipos consistentesFlexível, sem schema prévio
DesempenhoO menorMais eficiente que a stringO melhor

Convertendo uma string JSON em STRUCT

No exemplo do "John Doe", o schema é montado assim:

  1. Define-se o schema da string JSON, como um tipo STRUCT.
  2. As chaves name e age são STRING e INT.
  3. A chave address é um STRUCT com as chaves city e state.
  4. A chave children é um ARRAY de STRUCTs, cada um com name (STRING) e age (INT).
STRUCT<
    name: STRING,
    age: INT,
    address: STRUCT<city: STRING, state: STRING>,
    children: ARRAY<STRUCT<name: STRING, age: INT>>
>

Dois passos: schema_of_json e from_json

Passo 1: derivar o schema

Em vez de escrever o schema à mão, a função embutida schema_of_json o deriva de uma string JSON de exemplo e devolve a estrutura acima.

SELECT schema_of_json('{"name":"John Doe","age":35,"address":{"city":"Anytown","state":"CA"},"children":[{"name":"Ana","age":8}]}');

Passo 2: interpretar a coluna

Com o schema em mãos, o from_json recebe a string JSON e o schema e devolve uma coluna STRUCT com os dados interpretados.

SELECT
    from_json(
        json_column,
        'name STRING, age INT, address STRUCT<city: STRING, state: STRING>, children ARRAY<STRUCT<name: STRING, age: INT>>'
    ) AS struct_column
FROM minha_tabela;

O que guardar: o JSON tem objetos entre chaves com pares chave-valor, e os valores podem ser strings, números, booleanos, arrays ou objetos aninhados. Há três abordagens: STRING (simples, mas a menos performática), STRUCT (schema definido e mais eficiente nas consultas) e VARIANT (a mais nova, flexível e com o melhor desempenho). Converter JSON em STRUCT exige mapear os tipos JSON para os tipos SQL, e o schema_of_json deriva o schema de uma amostra, que o from_json aplica à coluna.
