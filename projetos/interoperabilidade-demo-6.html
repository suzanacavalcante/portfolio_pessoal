Implementing Lakehouse Federation

Data Interoperability with Unity Catalog · Demo 6

Em desenvolvimento

Esta demo, de cerca de 15 minutos, percorre o fluxo completo do Lakehouse Federation: criar um projeto Lakebase Postgres, popular uma pequena tabela de operações de loja, federá-la ao Unity Catalog como foreign catalog, e rodar uma consulta federada e um join entre sistemas com uma tabela fato TPC-DS nativa.

Estas anotações partem de um resumo da demo, não da transcrição. Segundo o resumo, a única legenda do vídeo está em chinês simplificado, e o resumo foi feito a partir dela. O resumo não traz o texto dos scripts, e por isso não escrevi código aqui.

Objetivo, requisitos e setup

A demo roda em serverless compute versão 5. O passo do Lakebase exige que a região do workspace suporte o Lakebase autoscaling.

O Lakebase é um Postgres gerenciado pela Databricks, para cargas OLTP, ao lado do lakehouse. A versão com autoscaling traz compute que escala até zero, branches e recuperação instantânea. Aqui ele faz o papel de um Postgres externo, então a mecânica de federação é a mesma de uma instância própria. Primeiro roda-se a célula de setup, que define o catálogo e o schema de trabalho do usuário.

Os passos

PassoO que acontece
1. Criar o projeto LakebaseNa UI: abrir o Lakebase pelo app switcher, escolher Lakebase Postgres e Create Project ("My Project", com os padrões). Depois de implantado, capturam-se o host (a parte do Postgres URI após o @, até o .com), o usuário e o OAuth token (em Connect e Copy OAuth Token), guardados em um arquivo de texto
2. Tabelas no LakebaseNo SQL Editor do Lakebase (banco databricks_postgres), o script padrão cria uma tabela de exemplo. Depois, um script da demo cria o schema tpcds_ops, recria a tabela store_ops e a preenche com dados gerados: 4 registros
3. Tabela no lado lakehouseCria-se, por CTAS a partir de outro schema, a tabela demo_store_sales_by_store no schema data_interoperability_tpcds. No Catalog Explorer aparece como Delta gerenciada
4. ConnectionAponta para o projeto Postgres. Precisa do host, do usuário e do OAuth token capturados no início. Valida-se com o DESCRIBE CONNECTION EXTENDED, e ela aparece em Catalog e Connections
5. Foreign catalogO CREATE FOREIGN CATALOG IF NOT EXISTS demo_store_ops_catalog, usando a connection e o banco principal databricks_postgres. O Catalog Explorer mostra o tipo foreign, e dá para navegar nos schemas (incluindo o tpcds_ops e a tabela store_ops)

Com isso há uma conexão federada completa entre o Lakebase (OLTP Postgres) e o Unity Catalog. Os comandos SQL, como o SHOW SCHEMAS e o DESCRIBE, e as consultas também funcionam por um notebook.

Diferença para a Demo 4: lá, a connection do SQL Server usava usuário e senha, e a do Snowflake, uma chave RSA. Aqui a autenticação é por OAuth token. Como o token do Lakebase é emitido pela própria Databricks, é provável que ele expire, mas o resumo não diz isso, e não tenho como confirmar.

Consulta e join entre sistemas

A consulta à store_ops retorna os dados fictícios inseridos. Depois, faz-se um join entre uma tabela do Lakebase e uma tabela do Unity Catalog, com GROUP BY e COUNT. As duas são tratadas como tabelas em schemas do mesmo ambiente: é uma consulta totalmente federada entre o OLTP Postgres e o lakehouse.

Pushdown

Uma agregação COUNT simples é enviada ao Postgres pela connection, e usa-se o EXPLAIN FORMATTED. O plano mostra que:

  • a consulta inteira foi enviada ao Lakebase e executada no Postgres;
  • só o resultado voltou ao notebook;
  • aparece o operador de pushdown e a indicação de que o select é executado pelo engine externo.

A conclusão é que o predicate pushdown é totalmente suportado: pela federação, o trabalho roda no sistema externo, para a máxima performance, e o resultado volta ao lakehouse.

Limpeza

Para repetir a demo, roda-se a célula de cleanup, que remove os objetos criados e permite uma execução limpa.

Ligação com as outras demos: o padrão connection + foreign catalog é o mesmo da Demo 4 e da Demo 5. O Lakebase Postgres também apareceu no tour pelo workspace, como o banco operacional gerenciado. As ligações são minhas.

O que guardar: um projeto Lakebase Postgres pode ser federado ao Unity Catalog como qualquer Postgres: uma connection (host, usuário e OAuth token) e um foreign catalog para o banco. Depois, as tabelas do Postgres se consultam e se juntam às do lakehouse em um mesmo SQL. O EXPLAIN FORMATTED confirma o pushdown: a consulta roda no Postgres, e só o resultado volta.
