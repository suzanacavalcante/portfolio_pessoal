Conditional and Iterative Tasks

Deploy Workloads with Lakeflow Jobs · Lição

Em desenvolvimento

Nesta lição, os workflows deixam de ser sequências lineares e passam a ramificar, repetir e decidir com base em dados e em resultados. Ela apresenta três tipos avançados de task: as dependências condicionais Run if, a task If/Else e a task For Each, que o curso usa para criar workflows dinâmicos e resilientes.

Estas anotações partem de um resumo da lição, não do material original. O resumo avisa que as etapas 2 e 3 do diagrama de execução e a maioria das notas "Saiba mais" não foram abertas. O diagrama desta página é meu.

Run if: dependências condicionais

O Run if dá um controle fino sobre a execução de uma task, segundo o resultado das tasks upstream. Estas são as condições da UI:

CondiçãoA task roda quando
All succeededTodas as dependências tiveram sucesso. É o padrão
At least one succeededAo menos uma teve sucesso. Mesmo que a Task-3 falhe, a Task-4 ainda roda
None failedNenhuma falhou e pelo menos uma foi executada
All doneTodas foram concluídas, com ou sem sucesso
At least one failedAo menos uma falhou
All failedTodas falharam

Representação visual no DAG

  • Os estilos e as cores das linhas indicam o tipo de dependência, o que visualiza a lógica.
  • Solução de problemas: quando algo falha, vê-se quais tasks foram afetadas e quais podem continuar.
  • Comunicação em equipe: o fluxo visual funciona como documentação para perfis técnicos e de negócio.

No exemplo da UI, a task Clean_Data depende da Ingest_Source_1, da Ingest_Source_2 e da Ingest_Source_3, com "Run if dependencies" igual a "All succeeded".

O fluxo de execução, em três etapas

  1. Job initialization: o sistema avalia as dependências e determina o conjunto inicial de execução. As três ingestões rodam ao mesmo tempo, e a task agregadora (All_Data_Ingested) fica Blocked.
  2. Waiting for all tasks to complete (All succeeded): a task dependente espera todas terminarem.
  3. Dependent task started: ao cumprir a condição, a task dependente inicia.

Task If/Else

Ela implementa a lógica de negócio direto no workflow, indo além do sucesso ou da falha para decisões baseadas em dados. Adiciona uma lógica booleana baseada nos resultados das tasks, e permite ramificar por verificações de qualidade de dados e por contagens de registros.

O exemplo é a checking_for_duplicates, que avalia uma condição (o valor igual a "true") com duas saídas, True e False. O ramo leva à dropping_duplicate_records, e a transforming_customers_sales roda com a condição "If none failed", que é o caso da pegadinha da Demo 4.

OperadorSignificado
==Igual
!=Diferente
> e >=Maior e maior ou igual
< e <=Menor e menor ou igual

Task For Each

É um padrão iterativo que mantém a gestão visual do workflow ao tratar operações repetitivas. O mecanismo:

  1. Um input array, como ["A","B","C"], é percorrido.
  2. A mesma task aninhada roda uma vez por item, recebendo o valor como {{input}}.
  3. A task downstream espera o conjunto todo.

As iterações podem rodar em paralelo, com uma concorrência configurável. As dependências downstream se ligam ao container For Each, e não à task aninhada.

Os dois componentes

1

A For Each task

O contêiner de nível superior, que gerencia o loop. Tem o nome (como customers_orders_state_wise_report_iterator), o tipo "For each", os Inputs (como ["CA","NY","VA"]), a Concurrency (opcional), o Depends on, o Run if dependencies e as notificações.

2

A nested task

A task que de fato executa a cada iteração, como um notebook "For Each: Customer orders State" em compute serverless.

Mais detalhes

  • Processamento dos inputs: cada item vai como {{input}} para a task aninhada, com a mesma lógica sobre partições diferentes.
  • Execução em paralelo: a concorrência configurável acelera as tarefas independentes.
  • Dependências: as tasks downstream dependem do container inteiro, o que garante que todas as iterações terminem.
  • Casos de uso: processamento geográfico (por estado ou região), por períodos, por segmento de cliente e por arquivo.
  • O container age como uma unidade lógica única no workflow, simplifica as dependências e gerencia os recursos entre as iterações.

O que guardar: o Run if controla a execução pelo resultado das tasks upstream, o If/Else acrescenta a ramificação booleana, com os operadores ==, !=, >, >=, < e <=, e o For Each itera sobre arrays com tasks aninhadas.
