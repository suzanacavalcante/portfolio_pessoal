O que são algoritmos

Um algoritmo é uma sequência finita de instruções bem definidas que resolve um problema. Toda a computação, de um cálculo simples ao reconhecimento facial, é feita de algoritmos.

Mesmo com a IA gerando código, entender algoritmos continua essencial. É isso que permite avaliar se uma solução gerada é eficiente e escalável, e escolher conscientemente entre alternativas. Para quem atua em arquitetura, a eficiência de uma solução é uma decisão de projeto, não um detalhe de implementação.

Um conceito antigo

  • O nome vem de al-Khwarizmi, matemático persa do século IX, autor de um tratado influente sobre cálculo.
  • O algoritmo de Euclides para o máximo divisor comum, de cerca de 300 a.C., é um dos primeiros formalmente descritos e ainda é ensinado.
  • Ada Lovelace escreveu, no século XIX, o primeiro algoritmo pensado para ser executado por uma máquina, a Máquina Analítica de Babbage.
  • No século XX, Alan Turing e John von Neumann estabeleceram as bases teóricas do que pode ser calculado.

Os três desafios de escrever um bom algoritmo

Tempo e memória

Eficiência

Resolver usando o mínimo de recursos. Mais otimização costuma significar mais complexidade de código, então é preciso decidir quando vale a pena.

Sem exceções

Correção

Funcionar para toda entrada válida. Como não dá para testar todas, os casos limite e a variedade de tamanhos importam.

Crescimento

Escalabilidade

O que funciona com 100 itens pode ser inútil com 100 milhões. O desempenho precisa se manter quando os dados crescem.

Como se constrói um algoritmo

  1. Definir entradas e saídas: que tipo de dado entra, o que deve sair.
  2. Dividir o problema em subproblemas menores ("dividir para conquistar") e abstrair os detalhes irrelevantes.
  3. Escolher as estruturas de dados adequadas, porque a escolha certa pode transformar uma solução inviável em uma rápida.
  4. Analisar a complexidade de tempo e de espaço antes mesmo de implementar.
  5. Escolher a estratégia de resolução (programação dinâmica, gulosa, backtracking e outras).
  6. Verificar e refinar: testes com casos limite e tamanhos variados, medindo o desempenho.
Análise de algoritmos

Análise de complexidade

Medir segundos em uma máquina depende do hardware. A análise de algoritmos olha para outra coisa: como o consumo de recursos cresce em relação ao tamanho da entrada. A notação mais usada é a Big O, que descreve esse crescimento no pior caso, tanto para tempo quanto para memória.

Um exemplo: buscar em uma lista

A busca linear olha item por item: no pior caso, 5.000 itens significam 5.000 comparações, ou seja, O(n). A busca binária exige a lista ordenada, mas descarta metade dos candidatos a cada passo: no pior caso, 5.000 itens significam cerca de 13 comparações, ou seja, O(log n). Para um bilhão de itens, são cerca de 30.

def busca_linear(lista, alvo):
    for i, valor in enumerate(lista):          # O(n)
        if valor == alvo:
            return i
    return -1


def busca_binaria(lista_ordenada, alvo):       # O(log n): exige lista ordenada
    baixo, alto = 0, len(lista_ordenada) - 1
    while baixo <= alto:
        meio = (baixo + alto) // 2
        if lista_ordenada[meio] == alvo:
            return meio
        if lista_ordenada[meio] < alvo:
            baixo = meio + 1                   # descarta a metade de baixo
        else:
            alto = meio - 1                    # descarta a metade de cima
    return -1
class Busca {

    static int linear(int[] v, int alvo) {                // O(n)
        for (int i = 0; i < v.length; i++) {
            if (v[i] == alvo) return i;
        }
        return -1;
    }

    static int binaria(int[] ordenado, int alvo) {        // O(log n): exige vetor ordenado
        int baixo = 0, alto = ordenado.length - 1;
        while (baixo <= alto) {
            int meio = baixo + (alto - baixo) / 2;        // evita estouro de int
            if (ordenado[meio] == alvo) return meio;
            if (ordenado[meio] < alvo) baixo = meio + 1;
            else alto = meio - 1;
        }
        return -1;
    }
}

    Estrutura certa, algoritmo mais rápido

    O clássico problema Two Sum pede os índices de dois números de um vetor que somam um alvo. A força bruta compara todos os pares: O(n²). Guardando em uma tabela hash os valores já vistos, cada elemento só precisa perguntar "o complemento que eu preciso já apareceu?", e a resposta vem em O(1). O algoritmo cai para O(n), em troca de O(n) de memória extra. Foi o meu primeiro desafio na plataforma (página do Two Sum).

class TwoSum {

    static int[] forcaBruta(int[] nums, int alvo) {          // O(n²)

    }

bool two_sum_forca_bruta(const int *nums, int n, int alvo, int r[2]) {
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (nums[i] + nums[j] == alvo) {
                r[0] = i; r[1] = j;
                return true;
            }
        }
    }
    return false;
}

/* C não traz tabela hash: aqui, uma tabela de endereçamento aberto feita à mão */
#define TAM 2048                          /* potência de 2, maior que 2n */

typedef struct { bool usado; int chave; int indice; } Entrada;

static unsigned posicao(int chave) {
    return ((unsigned)chave * 2654435761u) & (TAM - 1);
}

/* O(n) em média, O(n) de espaço. Supõe n < TAM / 2. */
bool two_sum(const int *nums, int n, int alvo, int r[2]) {
    Entrada *tabela = calloc(TAM, sizeof *tabela);
    bool achou = false;

    for (int i = 0; i < n && !achou; i++) {
        int complemento = alvo - nums[i];
        for (unsigned s = posicao(complemento); tabela[s].usado; s = (s + 1) & (TAM - 1)) {
            if (tabela[s].chave == complemento) {
                r[0] = tabela[s].indice; r[1] = i;
                achou = true;
                break;
            }
        }
        if (!achou) {
            unsigned s = posicao(nums[i]);
            while (tabela[s].usado) s = (s + 1) & (TAM - 1);
            tabela[s] = (Entrada){true, nums[i], i};
        }
    }
    free(tabela);
    return achou;
}
    Paradigmas

    Estratégias de resolução de problemas

    Poucos problemas são realmente novos. Reconhecer a família a que um problema pertence leva a um modelo mental pronto, e esse é o grande ganho de estudar estratégias.

    Dividir para conquistar

    Quebrar o problema em instâncias menores do mesmo tipo, resolver cada uma (em geral de forma recursiva, até um caso base trivial) e combinar os resultados. A etapa de combinar costuma ser a mais difícil de analisar. Exemplos: Merge Sort, Quick Sort e o algoritmo de Karatsuba para multiplicar números grandes. Os subproblemas independentes também se prestam bem à execução paralela e distribuída.

    Programação dinâmica

    Para problemas com subproblemas sobrepostos e subestrutura ótima. Em vez de recalcular o que já foi resolvido, guarda os resultados intermediários, como um cache. Pode ser top-down (recursão com memoização) ou bottom-up (tabulação, preenchendo uma tabela do menor para o maior). O trabalho principal é achar a relação de recorrência entre os estados. O Fibonacci recursivo ingênuo é O(2ⁿ) porque recalcula os mesmos valores. Com memoização ou tabulação, vira O(n).

    return n if n < 2 else fib_ingenuo(n - 1) + fib_ingenuo(n - 2)

class Fibonacci {

    static long ingenuo(int n) {                              // O(2^n)
        return n < 2 ? n : ingenuo(n - 1) + ingenuo(n - 2);
    }

    private static final Map<Integer, Long> memo = new HashMap<>();

    static long memoizado(int n) {                            // top-down: O(n)
        if (n < 2) return n;
        Long guardado = memo.get(n);
        if (guardado != null) return guardado;
        long resultado = memoizado(n - 1) + memoizado(n - 2);
        memo.put(n, resultado);
        return resultado;
    }

    static long tabulado(int n) {                             // bottom-up: O(n)
        long anterior = 0, atual = 1;
        for (int i = 0; i < n; i++) {
            long proximo = anterior + atual;
            anterior = atual;
            atual = proximo;
        }
        return anterior;
    }
}
    func FibIngenuo(n int) int { // O(2^n)

		return n

func FibMemo(n int, memo map[int]int) int { // top-down: O(n)
	if n < 2 {
		return n
	}
	if v, ok := memo[n]; ok {
		return v
	}
	memo[n] = FibMemo(n-1, memo) + FibMemo(n-2, memo)
	return memo[n]
}

	anterior, atual := 0, 1
	for i := 0; i < n; i++ {
		anterior, atual = atual, anterior+atual

    Algoritmos gulosos (greedy)

    A cada passo, escolhem a opção localmente ótima, sem reconsiderar, na esperança de chegar ao ótimo global. São simples e rápidos, mas só funcionam quando o problema tem a propriedade da escolha gulosa e subestrutura ótima. Exemplos: Dijkstra, seleção de atividades e troco de moedas.

    def troco(valor, moedas=(100, 50, 25, 10, 5, 1)):
    """Guloso: sempre a maior moeda que ainda cabe. Ótimo para este conjunto de moedas."""
    resultado = []
    for moeda in moedas:                    # moedas em ordem decrescente
        while valor >= moeda:
            valor -= moeda
            resultado.append(moeda)
    return resultado

    /* Guloso: sempre a maior moeda que ainda cabe.
   Preenche 'saida' com as moedas usadas e devolve a quantidade. */
int troco(int valor, int *saida) {
    const int moedas[] = {100, 50, 25, 10, 5, 1};   /* em ordem decrescente */
    int n = 0;
    for (int i = 0; i < 6; i++) {
        while (valor >= moedas[i]) {
            valor -= moedas[i];
            saida[n++] = moedas[i];
        }
    }
    return n;
}

    Cuidado: guloso nem sempre é ótimo. No conjunto de moedas {1, 3, 4}, para dar troco de 6 o guloso escolhe 4 + 1 + 1 (três moedas), enquanto a resposta ótima é 3 + 3 (duas). Nesse caso é preciso programação dinâmica. Antes de usar a abordagem gulosa, vale checar se a propriedade vale.

    Backtracking

    Uma força bruta refinada: constrói a solução passo a passo e, quando percebe que o caminho atual não pode dar certo, desfaz a última escolha e tenta a próxima alternativa. A poda dessa árvore de possibilidades é o que o diferencia da força bruta pura. Serve para problemas combinatórios e de satisfação de restrições: Sudoku, coloração de grafos, permutações e combinações.

    def subconjuntos_com_soma(nums, alvo):
    """Todos os subconjuntos de números positivos que somam 'alvo'."""
    nums = sorted(nums)
    resultado = []

    def explorar(inicio, atual, soma):
        if soma == alvo:
            resultado.append(list(atual))
            return
        for i in range(inicio, len(nums)):
            if soma + nums[i] > alvo:        # poda: os próximos só aumentam a soma
                break
            atual.append(nums[i])            # escolhe
            explorar(i + 1, atual, soma + nums[i])
            atual.pop()                      # desfaz (o "passo atrás")

    explorar(0, [], 0)
    return resultado

    static List<List<Integer>> comSoma(int[] nums, int alvo) {
        int[] ordenado = nums.clone();
        Arrays.sort(ordenado);
        List<List<Integer>> resultado = new ArrayList<>();
        explorar(ordenado, 0, alvo, new ArrayList<>(), resultado);
        return resultado;
    }

    private static void explorar(int[] nums, int inicio, int restante,
                                 List<Integer> atual, List<List<Integer>> resultado) {
        if (restante == 0) {
            resultado.add(new ArrayList<>(atual));
            return;
        }
        for (int i = inicio; i < nums.length; i++) {
            if (nums[i] > restante) break;           // poda
            atual.add(nums[i]);                      // escolhe
            explorar(nums, i + 1, restante - nums[i], atual, resultado);
            atual.remove(atual.size() - 1);          // desfaz (o "passo atrás")
        }
    }
}

		if restante == 0 {
			resultado = append(resultado, append([]int(nil), atual...))
			return
		}
		for i := inicio; i < len(ordenado); i++ {
			if ordenado[i] > restante {
				break // poda
			}
			atual = append(atual, ordenado[i]) // escolhe
			explorar(i+1, restante-ordenado[i])
			atual = atual[:len(atual)-1] // desfaz (o "passo atrás")
		}
	}
	explorar(0, alvo)
	return resultado
}

static int comparar(const void *a, const void *b) {
    return *(const int *)a - *(const int *)b;
}

static void explorar(const int *nums, int n, int inicio, int restante,
                     int *atual, int tamanho) {
    if (restante == 0) {
        for (int i = 0; i < tamanho; i++) printf("%d ", atual[i]);
        printf("\n");
        return;
    }
    for (int i = inicio; i < n; i++) {
        if (nums[i] > restante) break;                /* poda */
        atual[tamanho] = nums[i];                     /* escolhe */
        explorar(nums, n, i + 1, restante - nums[i], atual, tamanho + 1);
        /* "desfazer" é só voltar a usar 'tamanho': o valor antigo é sobrescrito */
    }
}

/* Imprime cada subconjunto de 'nums' (positivos) que soma 'alvo'. Supõe n <= 64. */
void subconjuntos_com_soma(int *nums, int n, int alvo) {
    int atual[64];
    qsort(nums, n, sizeof *nums, comparar);
    explorar(nums, n, 0, alvo, atual, 0);
}

    Janela deslizante

    Mantém uma "janela" de elementos adjacentes que se move pelo array ou pela string, atualizando o resultado de forma incremental em vez de recalcular tudo. A janela pode ter tamanho fixo (média móvel, maior soma de k elementos) ou variável (menor substring que contém certos caracteres, como no problema Minimum Window Substring). Transforma soluções O(n·k) ou O(n²) em O(n).

    def maior_soma_janela(nums, k):
    """Maior soma de k elementos consecutivos. Supõe len(nums) >= k."""
    janela = sum(nums[:k])                  # primeira janela
    melhor = janela
    for i in range(k, len(nums)):
        janela += nums[i] - nums[i - k]     # entra um elemento, sai outro
        melhor = max(melhor, janela)
    return melhor

    class JanelaDeslizante {

    // Maior soma de k elementos consecutivos. Supõe nums.length >= k.
    static long maiorSoma(int[] nums, int k) {
        long janela = 0;
        for (int i = 0; i < k; i++) janela += nums[i];     // primeira janela
        long melhor = janela;
        for (int i = k; i < nums.length; i++) {
            janela += nums[i] - nums[i - k];               // entra um, sai outro
            melhor = Math.max(melhor, janela);
        }
        return melhor;
    }
}

func MaiorSomaJanela(nums []int, k int) int {
	janela := 0
	for _, x := range nums[:k] { // primeira janela
		janela += x
	}
	melhor := janela
	for i := k; i < len(nums); i++ {
		janela += nums[i] - nums[i-k] // entra um, sai outro
		if janela > melhor {
			melhor = janela
		}
	}
	return melhor
}

    /* Maior soma de k elementos consecutivos. Supõe n >= k. */
long maior_soma_janela(const int *nums, int n, int k) {
    long janela = 0;
    for (int i = 0; i < k; i++) janela += nums[i];     /* primeira janela */
    long melhor = janela;
    for (int i = k; i < n; i++) {
        janela += nums[i] - nums[i - k];               /* entra um, sai outro */
        if (janela > melhor) melhor = janela;
    }
    return melhor;
}

    Meu método para resolver um problema

    Um roteiro que junta a teoria acima e que uso como checklist. É uma síntese minha, não uma regra da plataforma.

    1. Entender: entradas, saídas e restrições. O tamanho máximo de n indica a complexidade aceitável: com n até uns 20, até exponencial passa; com n em torno de 10⁵, é preciso O(n log n) ou melhor.
    2. Exemplificar: resolver à mão os exemplos do enunciado e listar casos limite (vazio, um elemento, valores repetidos, negativos).
    3. Começar pela força bruta: uma solução correta, mesmo lenta, serve de referência para testar as otimizações.
    4. Otimizar: perguntar "que estrutura de dados ou estratégia reduz o trabalho repetido?".
    5. Implementar e testar com os exemplos e os casos limite.
    6. Declarar a complexidade de tempo e de espaço.
    7. Comparar com outras soluções e com as discussões, para aprender a abordagem que não ocorreu.

    O que levo daqui

    • Um algoritmo não precisa só estar certo: precisa ser eficiente e escalar, e a análise de complexidade é a ferramenta para isso.
    • A estrutura de dados certa muda a classe de complexidade da solução, como o Two Sum mostra com a tabela hash.
    • Estratégias (dividir para conquistar, programação dinâmica, guloso, backtracking, janela deslizante) são modelos mentais que se reconhecem em problemas novos.
    • Complexidade e arquitetura se encontram: escolher entre abordagens com Big O diferente é uma decisão sobre custo e escala do sistema.
    • Praticar de forma contínua, com a força bruta primeiro e a otimização depois, vale mais do que decorar soluções.
