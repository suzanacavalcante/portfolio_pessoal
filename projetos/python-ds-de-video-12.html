Scaling Pandas with Spark

Introduction to Python · Vídeo 12 de 13

Em desenvolvimento

O Pandas é ótimo, mas roda em uma única máquina. Este módulo mostra como levar a sintaxe do Pandas à escala do Spark com a Pandas API on Spark: como ela se relaciona com o Pandas e o PySpark, três formas de ler o mesmo CSV, os tipos de índice, as conversões entre os tipos de DataFrame e as operações comuns (value_counts, gráficos e SQL).

Os trechos de código abaixo são exemplos escritos por mim com base no resumo da demonstração, não a cópia do notebook do curso. Eles dependem de um ambiente Spark, como o do Databricks, e não foram executados fora dele. O ambiente é o de sempre: Serverless Environment Version 5, com o ambiente base em Standard Version 5, e a tabela disponível é a sf_airbnb.

O internal frame

O internal frame é um objeto interno que faz a ponte entre a interface estilo Pandas e o DataFrame Spark que fica por baixo. Ele guarda o DataFrame Spark e metadados, como o mapeamento dos nomes de colunas e do índice.

Cada operação cria um novo internal frame, e esse passo extra gera uma sobrecarga em relação ao Spark nativo. Em casos muito sensíveis a desempenho, quem faz engenharia de dados pode preferir o Spark SQL nativo. Na maioria dos casos, o ganho de produtividade compensa.

Lendo o mesmo CSV de três formas

1. PySpark

spark_df = spark.read.csv(
    caminho,
    header=True,        # a primeira linha são os nomes das colunas
    inferSchema=True,   # detecta os tipos
    multiline=True,     # campos com quebra de linha, como descrições de anúncios
    escape='"',         # campos entre aspas que contêm vírgulas
)
display(spark_df)

2. Pandas

Todo o dataset fica na memória de uma única máquina. Com 7 mil linhas tudo bem, mas com 7 milhões ou 700 milhões o código pode falhar por falta de memória.

import pandas as pd

pdf = pd.read_csv(caminho)

3. Pandas API on Spark

O resultado é um DataFrame distribuído, com índice gerado automaticamente. Quem já sabe Pandas só precisa trocar pd por ps.

import pyspark.pandas as ps

psdf = ps.read_csv(caminho)

Tipos de índice

Em um sistema distribuído não há acordo automático sobre qual linha recebe qual índice, e gerar um índice sequencial exige coordenar todas as partições, o que é caro. Por isso existem três opções:

TipoQuando usar
sequenceDados pequenos ou cluster de nó único
distributedDados grandes ou clusters com vários nós
distributed-sequenceMelhor compatibilidade, com algum custo de desempenho. É o padrão recomendado para a maioria dos casos e o mais seguro ao migrar código Pandas existente

A configuração é global para a sessão:

ps.set_option("compute.default_index_type", "distributed-sequence")

Convertendo entre os tipos de DataFrame

DeParaComoObservação
SparkPandas APIps.DataFrame(spark_df) ou spark_df.pandas_api()Não copia os dados, só adiciona a interface Pandas. O resultado não tem coluna de índice
Pandas APISparkpsdf.to_spark()Útil para gravar em tabela Delta ou passar a pipelines de ML do Spark. O índice some
Pandas APIPandaspsdf.to_pandas()Junta tudo em uma máquina
 
psdf = spark_df.pandas_api()    # Spark -> Pandas API
spark_de_volta = psdf.to_spark()  # Pandas API -> Spark
pdf = psdf.to_pandas()          # Pandas API -> Pandas

Cuidado com o to_pandas(): ele junta todos os dados em uma única máquina. Só use depois de filtrar ou agregar para um tamanho gerenciável, senão pode travar com milhões de linhas.

A Pandas API pode gerar avisos (UserWarning) sobre diferenças de comportamento em relação ao Pandas. Na demonstração eles foram suprimidos, mas no trabalho real vale ler.

Operações comuns

value_counts

No Spark nativo são três passos: agrupar, contar e ordenar de forma decrescente. Na Pandas API é uma única chamada.

from pyspark.sql import functions as F

# Spark nativo: groupBy, count e orderBy descendente
spark_df.groupBy("property_type").count().orderBy(F.desc("count"))

# Pandas API on Spark
psdf["property_type"].value_counts()

Gráficos

O hist e o boxplot funcionam como no Pandas, e a execução é otimizada para cada tipo de gráfico. Os gráficos de barras usam por padrão só as primeiras 1.000 linhas, e isso pode ser ajustado.

ps.set_option("plotting.max_rows", 5000)

SQL

Dá para misturar transformações estilo Pandas com SQL, conforme for mais claro em cada passo.

ps.sql("SELECT DISTINCT property_type FROM {df}", df=psdf)

Recursos adicionais

  • Lê diretamente de tabelas Delta e de diretórios com vários arquivos.
  • O .apply tem um atalho: com menos de 1.000 linhas, usa Pandas puro internamente. Ele exige anotar o tipo de retorno da função, como nas UDFs do Spark.
  • Planos de execução (explain) e cache de DataFrames também existem, com uma sintaxe menos intuitiva que a do Spark nativo.

O que guardar: a Pandas API on Spark leva a sintaxe do Pandas à escala do Spark, ao custo de alguma sobrecarga. O mesmo dataset pode ser lido com as três abordagens, e o tipo de índice afeta desempenho e exatidão (o distributed-sequence é o mais seguro). Dá para converter entre PySpark e Pandas API, e value_counts, gráficos e SQL funcionam com sintaxe parecida com a do Pandas.
