Appending Metadata Columns on Ingest

Data Ingestion with Lakeflow Connect · Lição

Em desenvolvimento

Esta lição explica como anexar colunas de metadados, como o nome do arquivo de origem e o horário de modificação, durante a ingestão a partir do armazenamento em nuvem. O recurso é a coluna _metadata, e o ganho é preservar o contexto de cada linha na criação da tabela no Lakehouse.

Estas anotações partem de um resumo da lição, não do material original. O exemplo de código é meu, com caminho e nomes genéricos, e não foi executado.

Objetivos

  1. Explicar o propósito das colunas de metadados e o valor delas na ingestão.
  2. Usar a coluna _metadata para anexar metadados em nível de arquivo (nome e hora de modificação) ao criar a tabela.
  3. Identificar os campos comuns de _metadata, como _metadata.file_name e _metadata.file_modification_time.

Adicionando uma coluna de metadados

Dá para acrescentar informações dos arquivos de origem ao criar a tabela. O fluxo tem quatro passos:

1

Arquivos brutos

O armazenamento em nuvem tem arquivos em CSV, TXT, JSON ou outros formatos. No exemplo, uma tabela raw_file com as colunas users e unix_ts.

2

Tabela Delta

A ideia é ingerir esses arquivos em uma tabela de nível Bronze.

3

Colunas de metadados

Na ingestão, acrescentam-se colunas com a origem: o horário da última modificação do arquivo e o nome do arquivo de onde a linha veio.

4

Tabela Bronze

O resultado tem as colunas originais mais as de metadados (no exemplo, last_mod_time e source).

Isso preserva o contexto da origem dos dados, o que é útil para auditoria, linhagem e depuração.

Campos comuns de metadados de arquivo

Para adicionar essas colunas, usa-se a coluna especial _metadata, uma coluna oculta, disponível para todos os formatos de arquivo de entrada. Dois campos são comuns:

CampoO que éExemplo
_metadata.file_modification_timeO timestamp da última modificação do arquivo2024-10-07T18:04:42.885+00:00
_metadata.file_nameO nome do arquivo de origem de cada linhapart-00002-...

Atenção: como a _metadata é oculta, para que ela apareça no DataFrame retornado é preciso selecioná-la explicitamente na consulta de leitura, ao especificar a origem.

CREATE TABLE raw_file_bronze AS
SELECT
    *,
    _metadata.file_modification_time AS last_mod_time,
    _metadata.file_name              AS source
FROM read_files(
    'caminho_do_volume/origem',
    format => 'csv'
);

O que guardar: as colunas de metadados preservam o contexto da origem dos dados, o que vale para auditoria, linhagem e depuração. A _metadata é oculta e existe para todos os formatos, mas precisa ser selecionada explicitamente na consulta de leitura. Os dois campos mais usados são _metadata.file_modification_time e _metadata.file_name. A próxima etapa é a prática com essas colunas para enriquecer os dados ingeridos.
