Exploring the Lab Environment

Data Ingestion with Lakeflow Connect · Demo 1

Em desenvolvimento

Esta demo, de cerca de 6 minutos, não ingere nada ainda. Ela mostra todos os objetos de dados do Unity Catalog e os recursos que serão usados nas demos seguintes: o catálogo e o schema do aluno, o volume com arquivos CSV, JSON e XML, uma tabela e o catálogo compartilhado que serve de fonte dos dados.

Estas anotações partem de um resumo da demo com marcação de tempo, não da transcrição. Os comandos SQL abaixo são exemplos escritos por mim a partir desse resumo, com nomes genéricos no lugar dos objetos do curso, e não foram executados.

Setup

Primeiro, conecta-se a um compute serverless (a versão mais recente) e roda-se o script de configuração da sala de aula. Ele faz quatro coisas:

  • define o catálogo padrão como o catálogo labuser..., que é diferente para cada aluno;
  • define o schema data_ingestion como schema padrão;
  • cria um volume com três diretórios;
  • cria uma tabela do Unity Catalog.

Explorando pelo Catalog Explorer

Pelo ícone de catálogo no painel esquerdo, o catálogo do aluno tem três schemas:

SchemaO que é
data_ingestionO schema de trabalho do curso
defaultCriado automaticamente em todo catálogo novo
information_schemaTambém criado automaticamente, e guarda metadados

Dentro de data_ingestion há uma tabela, recém-criada, e, em Volumes, a pasta landing, com três subpastas de arquivos: CSV, JSON e XML. Elas serão usadas nas próximas demos.

Catálogo compartilhado: o dbacademy_ecommerce foi criado a partir do Marketplace e é a fonte dos dados que serão carregados para os volumes do aluno.

Definindo catálogo e schema com SQL

Os mesmos efeitos do script podem ser obtidos por comandos SQL. Usa-se IDENTIFIER(...) para referenciar uma variável como nome de catálogo. O schema tem o mesmo nome para todos os usuários (data_ingestion), e o current_catalog() e o current_schema() confirmam o resultado: o catálogo labuser<número> e o data_ingestion.

USE CATALOG meu_catalogo;
USE SCHEMA data_ingestion;

SELECT current_catalog(), current_schema();

Volumes

Os volumes servem para guardar dados e arquivos no Unity Catalog, e deles se criam tabelas depois. Também podem armazenar funções e modelos de ML.

No volume de origem, do dbacademy_ecommerce, há pastas como delta e raw. Dentro de raw ficam sales_historical e user_historical. A pasta user_historical tem:

  • quatro arquivos part em Parquet;
  • três arquivos de metadados, cujos nomes começam com _.

A listagem mostra a data de modificação e o tamanho de cada arquivo. O DESCRIBE VOLUME mostra as propriedades do volume, como o tipo (gerenciado) e o tipo de securable.

DESCRIBE VOLUME meu_volume;

O que guardar: o script de setup deixa pronto o catálogo do aluno com o schema data_ingestion, um volume landing com arquivos CSV, JSON e XML e uma tabela. Os dados de origem vêm do catálogo compartilhado dbacademy_ecommerce, do Marketplace, e os arquivos de exemplo ficam em Parquet no volume de origem. Dá para explorar tudo pelo Catalog Explorer ou por SQL (SHOW SCHEMAS, DESCRIBE SCHEMA EXTENDED e DESCRIBE VOLUME). Na próxima demo, os dados serão ingeridos, com mais técnicas de ingestão.
