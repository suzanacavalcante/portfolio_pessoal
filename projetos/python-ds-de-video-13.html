Onde o código roda: local e on-premise

Local

É o laptop ou o desktop, com Jupyter, VS Code ou scripts na linha de comando. A memória (RAM), o armazenamento e a CPU são fixos. Serve bem para CSVs e planilhas com alguns milhares de linhas, mas não para logs, clickstream, telemetria de IoT e transações contínuas.

On-premise

A organização compra e opera os próprios servidores em um data center. Há mais poder e controle, e o hardware pode ser dedicado. Em contrapartida, é preciso comprar, instalar, manter, aplicar patches, proteger, monitorar e planejar a capacidade.

  • Subestimar a capacidade prejudica o desempenho, e superestimar deixa máquinas caras ociosas.
  • Escalar é lento: aquisição, rede e implantação levam tempo.

Computação em nuvem

Na nuvem, aluga-se compute e armazenamento de um provedor (AWS, Azure ou Google Cloud): pedem-se recursos quando necessário e liberam-se quando acaba. Há três vantagens:

1

Custo inicial menor

Não é preciso comprar hardware antes de começar.

2

Elasticidade

Escalar para cima e para baixo conforme a demanda.

3

Acessibilidade

Equipes em locais diferentes usam a mesma plataforma.

Atenção: a nuvem não é sempre mais barata. A economia é mais flexível quando a demanda varia.

Máquinas virtuais (VMs)

Uma VM é um computador definido por software (CPU, memória, armazenamento e rede), criado sobre um servidor físico maior. Um servidor hospeda várias VMs, isoladas entre si. O provedor pode criar, redimensionar ou desligar VMs sob demanda, o que se chama de compute elástico.

No Databricks, o seu código não roda na CPU do seu laptop: ele orquestra compute em nuvem, muitas vezes em VMs, em seu nome.

Armazenamento em nuvem

Na nuvem, compute e armazenamento são separados. O armazenamento costuma ser object storage, que guarda CSVs, Parquet, imagens, vídeos, PDFs, logs e artefatos de machine learning, e escala bem.

A ideia-chave: o compute vem e vai, e os dados ficam. Sobe-se um ambiente por uma hora, processam-se dados do S3, gravam-se os resultados e desliga-se o compute. O Databricks lê e escreve no object storage e gerencia a camada de compute separadamente.

Databricks sobre a nuvem, com o Spark

O Databricks roda em cima do provedor de nuvem e não o substitui. Oferece um workspace integrado, com notebooks, pipelines, jobs agendados, treino de modelos de machine learning e dashboards, tudo com governança. Ele abstrai grande parte da complexidade da infraestrutura, e é uma plataforma compartilhada entre engenheiros, analistas, cientistas e usuários de negócio.

Apache Spark

O Spark é o motor de compute distribuído: divide um dataset grande em partições, distribui entre várias máquinas e processa em paralelo. No cluster, há dois papéis:

  • o driver coordena: planeja o job e envia as tarefas;
  • os workers processam as partições.

No serverless compute, boa parte do gerenciamento de cluster some: você roda o código, e a plataforma provisiona e escala os recursos.

Unity Catalog

É a camada de governança unificada: o Spark cuida do compute, e o Unity Catalog cuida da organização, das permissões e da descoberta.

Os objetos são endereçados por um namespace de três níveis: catálogo.schema.objeto, em que o objeto pode ser uma tabela, uma view ou uma função. Um exemplo do curso é dbacademy.labuser....sf_airbnb.

A exploração pode ser feita com SQL: listar catálogos, listar os schemas de um catálogo e listar as tabelas de um schema.

SHOW CATALOGS;

SHOW SCHEMAS IN samples;

SHOW TABLES IN samples.tpch;

No exemplo do catálogo samples e do schema tpch, a demonstração lista 9 tabelas, entre elas customer, lineitem, nation, orders e part. A lição é que os dados são organizados, governados e referenciados por um namespace formal, o que facilita a colaboração e a segurança em escala.

Git e GitHub

  • Git é um sistema de controle de versão: registra as mudanças, permite reverter erros, criar branches e fazer merge.
  • GitHub é a plataforma hospedada de repositórios Git, com colaboração e revisão por pull requests.

O controle de versão vale para notebooks, scripts, SQL e arquivos de configuração. O Databricks integra provedores Git por meio das Git folders.

O que guardar: o código pode rodar localmente, on-premise ou na nuvem, e a nuvem traz custo inicial menor, elasticidade e acessibilidade, nem sempre com menor custo. VMs dão compute elástico, e o object storage guarda os dados separados do compute. O Databricks fica sobre a nuvem, com o Spark (driver e workers) para o compute distribuído, o serverless para tirar o gerenciamento de cluster e o Unity Catalog para a governança. Git e GitHub cuidam do controle de versão. Esta é a última demonstração do curso, e o módulo final traz recursos adicionais.
