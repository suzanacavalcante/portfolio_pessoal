Errors and Exceptions

Introduction to Python · Vídeo 6 de 13

Em desenvolvimento

Todo programa encontra erros, e saber lê-los e tratá-los faz parte de escrever código confiável. Este módulo mostra a diferença entre erros de sintaxe e exceções, como tratar exceções com try e except, tipos específicos e múltiplos de exceção, o uso de else e finally e a instrução assert.

Os trechos de código abaixo são exemplos escritos por mim com base no que a demonstração descreve, não a cópia do notebook do curso. O ambiente é o mesmo dos módulos anteriores: Serverless Environment Version 5, com o ambiente base em Standard Version 5.

Erros de sintaxe

Um erro de sintaxe acontece quando o Python não consegue ler a estrutura do código. Ele para antes de avaliar a lógica: o programa nem começa a rodar. O exemplo da demonstração é um if sem os dois-pontos no final.

idade = 20

if idade >= 18       # falta o ":" no final da linha
    print("maior de idade")
# SyntaxError: expected ':'

O Genie Code pode sugerir a correção. Algumas dicas para achar erros de sintaxe:

  • conferir os dois-pontos depois de if, for e while;
  • procurar parênteses e colchetes desbalanceados;
  • ver se há palavras-chave no lugar errado.

Exceções

Uma exceção é diferente: o código é gramaticalmente válido, mas falha durante a execução. O exemplo clássico é dividir por zero. Nesse caso, o Python cria um objeto de exceção (raise) e interrompe o fluxo, a menos que algo o capture.

print(1 / 0)
# ZeroDivisionError: division by zero

try e except

Com try, o Python tenta executar um bloco. Se der uma exceção, ele executa o bloco do except em vez de deixar o programa falhar.

try:
    resultado = 1 / 0
except ZeroDivisionError:
    print("Não é possível dividir por zero")

print("O programa continua")   # o código depois do except segue normalmente

Mau hábito: um except vazio captura qualquer exceção. É amplo demais: esconde erros que ninguém previu e dificulta achar a causa. O melhor é nomear a exceção esperada.

Exceção específica e múltiplas

Usar except ZeroDivisionError: trata só esse tipo. Uma exceção que não está na lista, como um NameError, ainda derruba o programa. Para tratar várias exceções no mesmo bloco, passa-se uma tupla:

try:
    print(undefined_variable)
except (ZeroDivisionError, NameError):
    print("Divisão por zero ou nome não definido")

Guardando a exceção com as e

Com except ... as e, a exceção fica guardada em uma variável, e dá para imprimi-la para ver a mensagem de erro.

try:
    print(undefined_variable)
except NameError as e:
    print(e)   # name 'undefined_variable' is not defined

Dois pontos sobre o comportamento:

  • O Python trata uma exceção por vez. Quando dá erro, as linhas seguintes dentro do try não rodam.
  • O código depois do except continua normalmente.
try:
    print("antes do erro")
    1 / 0
    print("esta linha nunca roda")
except ZeroDivisionError as e:
    print("erro tratado:", e)

print("depois do try/except")

else: o ramo de sucesso

O bloco else roda só se o try terminar sem exceção. É o ramo de sucesso, como na divisão 10 / 2.

try:
    resultado = 10 / 2
except ZeroDivisionError:
    print("Divisão por zero")
else:
    print("Deu certo:", resultado)   # Deu certo: 5.0

finally: roda sempre

O bloco finally roda sempre, com ou sem exceção. É o lugar para a limpeza: fechar arquivos, liberar conexões de banco de dados e encerrar requisições de rede.

try:
    resultado = 10 / 0
except ZeroDivisionError:
    print("Divisão por zero")
else:
    print("Deu certo:", resultado)
finally:
    print("Limpeza: este bloco roda de qualquer jeito")

assert

A instrução assert verifica uma condição. A sintaxe é assert condição, "mensagem opcional":

  • Se a condição for verdadeira, nada acontece.
  • Se for falsa, gera um AssertionError, com a mensagem, se houver.
idade = 20
assert idade >= 18, "A idade deve ser de pelo menos 18"   # passa em silêncio

idade = 15
assert idade >= 18, "A idade deve ser de pelo menos 18"
# AssertionError: A idade deve ser de pelo menos 18

Serve para checar os seus próprios pressupostos, em desenvolvimento e em testes. Não substitui o try/except, que trata falhas esperadas durante a execução.

O que guardar: erro de sintaxe impede o programa de rodar, e exceção acontece durante a execução. O try/except captura exceções, de preferência nomeando o tipo esperado, e as e guarda a mensagem. O else é o ramo de sucesso, o finally roda sempre e serve para limpeza, e o assert confere pressupostos durante o desenvolvimento.
