Course Project Overview

Deploy Workloads with Lakeflow Jobs · Lição

Em desenvolvimento

O objetivo desta lição é apresentar o projeto do curso: um pipeline de processamento de dados de varejo (retail) que demonstra todos os conceitos do Lakeflow Jobs. A lição é um diagrama interativo em sete passos, que vai montando o pipeline aos poucos.

Estas anotações partem de um resumo da lição, não do material original. O resumo avisa que os rótulos dentro do diagrama são pequenos e que só o que estava legível foi transcrito. O diagrama desta página é meu, desenhado a partir da descrição.

Os sete passos

  1. Cloud Storage: o ponto de partida. Os dados de varejo (Retail Data) ficam no armazenamento em nuvem.
  2. Ingesting Data: três tasks de ingestão, a Ingesting Orders (Notebook task), a Ingesting Customers (SQL task) e a Ingesting Sales (Notebook task).
  3. Joining Data: duas tasks Notebook de junção. A Joining Customers & Orders usa as ingestões de customers e orders, e a Joining Customers & Sales usa customers e sales.
  4. If/Else Block: sobre o resultado de customers e sales. Verifica-se se há duplicatas em customers_sales: se sim (True), uma task remove as duplicatas, e se não (False), aplica-se a lógica de transformação.
  5. For Each Task: sobre customers_orders. Um iterador executa uma task em loop, e a "loop condition" faz a transformação em cada iteração.
  6. Transforming Data: uma task Notebook transforma a customers_orders depois do For Each.
  7. Dashboard Creation: uma task de Dashboard (o "Retail Dashboard") consome os resultados das duas ramificações, a do If/Else e a do For Each com a transformação.

Os conceitos que o projeto reúne

Tasks

Tipos de task

Notebook, SQL e Dashboard.

Dependências

If/Else e For Each

O fluxo condicional e a iteração.

Tudo isso é orquestrado ponta a ponta, com um dashboard final.

Como isso aparece nas demos

As demos do curso constroem esse pipeline passo a passo:

  • Demo 1: um job com duas tasks de ingestão, uma de notebook e uma de SQL;
  • Demo 3: a terceira ingestão, a de clientes, com o gatilho de chegada de arquivo;
  • Demo 4: as junções, o If/Else e o For Each;
  • Demo 6: a transformação, o reparo de uma tarefa e a task de dashboard, que fecha o pipeline.

Uma diferença que notei: neste resumo da lição, a Ingesting Customers é uma SQL task, e a Ingesting Sales é uma Notebook task. Nos resumos das demos, é o contrário: a ingestão de vendas é uma query SQL, e a de clientes é um notebook. Como o próprio resumo avisa que os rótulos do diagrama eram pequenos, pode ser só um erro de leitura. Vale conferir na lição original.

O que guardar: o projeto do curso é um pipeline de varejo em sete passos: o armazenamento em nuvem, a ingestão em três tasks, as junções, o If/Else sobre as duplicatas, o For Each sobre os pedidos, a transformação e o dashboard final. Ele reúne os tipos de task, as dependências do DAG, o controle de fluxo condicional, a iteração e a orquestração ponta a ponta.
